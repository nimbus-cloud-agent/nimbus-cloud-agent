# Nimbus web UI

React 19.3.1 + HeroUI v3.2.7 + Tailwind 4.3.3, built with Vite 8.3.5 and TypeScript 7.0.2. HeroUI is the sole component library; xterm.js supplies the terminal. No HeroUIProvider or Tailwind PostCSS configuration is used.

`npm ci && npm run build` creates `dist/`, embedded by the Go binary. For UI development use `npm run dev` with Nimbus on 127.0.0.1:8080. The Vite development proxy handles REST, SSE, and WebSocket; production has no separate frontend server.

`App.tsx` subscribes to `/api/sessions/stream` for the workspace list. Selecting a session fetches exactly one newest `/events` page of outbox rows, turn summaries, and page-scoped questions, then subscribes to the lightweight `/stream?since_turn=…` summary lane. Older keyset pages (`before_turn`) load only after an upward wheel, touch, or keyboard gesture near the top, retain the visible reading anchor, and merge without replacing concurrent live updates. Neither this history endpoint nor the main SSE lane carries native events or frames. Session changes cancel pending requests and close streams; history errors offer an explicit retry.

The workspace is chat-first, with a single 48px header and no mobile tabs. At 1100px and above sessions use a desktop sidebar (compact below 1440px, expanded by default at 1440px); the header toggle changes its width. Narrower screens use a sessions drawer, closed automatically after session or Library selection. Focus mode temporarily hides the sidebar and terminal, restoring both on exit. The composer grows with its draft and available width, retaining unsent text across terminal toggles and resizing. Below 768px, a compact model-options button replaces inline Plan/reasoning controls. Prose stays within 1040px while code blocks and tables can use the wider chat surface.

The terminal starts closed, including for running sandboxes, and mounts only when explicitly opened. It splits beside chat only when at least 720px of chat and 320px of terminal fit after the sidebar; otherwise it opens in an overlay (fullscreen on phones). Closing it unmounts xterm and closes its WebSocket. Library selection, the sessions drawer, and terminal overlays pause hidden chat history/detail queries without discarding cached pages or reading position; returning resumes the summary stream against that cache. Split-terminal chat stays live.

The model label is fixed to DeepSeek Flash. Plan/thinking remain editable, while the preset picker uses the server's `mode_locked` field and disables immediately during submission. `ImageGallery.tsx` renders draft previews and historical images; the composer supports upload, paste, drag/drop, and image-only messages. Image bytes are served separately from SSE.

Tool presentation follows the installed DSH Web UI's `ToolRow`, `ToolCallTree`, and turn-process disclosure structure, implemented with HeroUI Accordion and Button. Completed processes start collapsed and make no detail requests until opened; active processes start open. `TurnTrace.tsx` requests `/turns/:tid/events?projection=metadata&parent_call_id=root` for an open process: bounded tool-header arguments, assistant text, reasoning-presence flags, and pending tool IDs, never full arguments, results, reasoning, or frame replay. Opening a tool requests its exact `call_id` trace and direct child headers; nested child bodies wait for their own disclosure. Reasoning folds query only their native `seq` or attempt's reasoning frames. The matching scoped `/stream` lanes run only while their owning folds are expanded and execution is active. Per-session query/disclosure caches retain explicit choices, lossless records, and composite native-event/frame watermarks across collapse/reopen; completion catches up consistent snapshots before a running cache becomes terminal. Query errors offer a retry. Final answers, images, and plan controls remain outside the execution fold; main questions contain metadata only, plan content loads when reviewed, and failed-review summaries contain only the exact native sequence needed for an explicit retry. Detail queries explicitly omit duplicate outbox/questions. `tool-events.ts` joins scoped native records by call ID and preserves pending/interrupted output. Activity inspection requests raw traces explicitly per turn, never globally.

Activity uses separate bounded native-event/frame header queries (`projection=headers&kind=events|frames&limit=100`); frame headers wait for their own section to open. Older header pages require an explicit button, and newer header SSE merges without rewinding its composite cursor. Individual record folds request only `seq` or `frame_id`, so opening a turn never hydrates all native payloads or token frames.

While a tool's arguments stream, its card starts expanded and shows the raw JSON text received so far, even before that JSON is complete. Incoming deltas append without resetting an explicit fold choice; the text is escaped, selectable, and copyable. Once the native `tool/call` event arrives, the regular typed tool card replaces the preview without duplication. Character counts remain a progress indicator, not a replacement for the parameter text.

Library deliverables are shared as Markdown links such as `[Preview](nimbus://library/<UUID>)`. The Markdown renderer allows only valid Library URLs in link destinations, while retaining the default sanitizer for other URLs; URLs inside code remain literal code. HTML previews allow scripts inside an opaque-origin sandbox so interactive content can render without gaining access to the surrounding app.

`node scripts/tool-ui-check.mjs` from the repository root tests folding, nested calls, keyboard interaction, copying, stream updates, and mobile layout against browser-only fixtures. They make no model/tool calls and do not modify stored conversations. For deterministic request-count checks, run `npm run build --prefix web`, serve it with `npx vite preview --host 127.0.0.1 --port 5174` from `web/`, and set `NIMBUS_UI_URL=http://127.0.0.1:5174`. The Vite development server enables React StrictMode effect replay and is not suitable for exact request counts. `npm test` at the root includes native tool-event projection tests.

`node scripts/lazy-history-check.mjs` exercises newest-page loading, idle network silence, upward-only pagination with stable anchoring, concurrent live merges, metadata-only process expansion, lazy tool bodies/retry, composite reconnect cursors, completion catch-up, stale session-request isolation, header-only Activity inspection, and hidden-panel query/socket cleanup with browser-only fixtures. It also checks chat width allocation, sidebar/focus restoration, responsive split/overlay terminals, draft retention, composer growth, and page overflow. `node scripts/library-lazy-check.mjs` includes narrow-screen drawer navigation while preserving lazy fetch and cancellation assertions.

Build the root project after changing the production UI, then restart Nimbus and reload the page. `node scripts/session-updates-e2e.mjs` from the repository root checks these interactions in Chrome and uses real DeepSeek/E2B credentials.
